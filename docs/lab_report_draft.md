# ЛР 3. Проверка LLM на задачах машинного обучения

**Технический черновик по сохранённым результатам, 29.10.2026.** Подготовлен с помощью ИИ. Оценки C/D/F предварительные; независимая проверка людьми не завершена. По заданию авторы должны самостоятельно написать окончательные выводы. Новые результаты следует пересчитать тетрадью, а числа этого черновика обновить перед сдачей.

## 1. Гипотезы и прогноз

Проверяются H3 (недостаток данных), H5 (разрыв малой и больших моделей на расчётных/концептуальных задачах), H12 (few-shot классификация против LogReg). Протокол и новые контрольные задания зафиксированы в коммите [b39894f](https://github.com/SlavaLEVIN/bmstu-ml-lab3-llm/commit/b39894f), после пилота, до новых ответов. Прогнозы ассистента: H3 — не подтвердится; H5 — подтвердится; H12 — не подтвердится. Это не прогноз студентов до первоначальных 108 ответов. Подробности: [протокол](experiment_protocol.md).

## 2. Методика

| Модель | Способ запуска | Параметры |
|---|---|---|
| GigaChat-3-Ultra | API Сбера | temperature=0.0001 |
| gpt-6.1-sol | API через LLM Gate | reasoning_effort=low |
| Qwen/Qwen3-4B-Instruct-2507 | собственная генерация на T4 в Colab | FP16, do_sample=False, seed=42 |
| t-tech/T-lite-it-2.1 | подготовлен запуск на T4 | NF4 4 bit; результатов пока нет |

API-провайдер сообщает идентификатор GPT; независимо проверить происхождение весов посредника нельзя. Даты, ревизии открытых весов, запросы, лимиты, usage и окружение сохранены в JSONL и `reproducibility/`. Исходный банк запускался 28–29.10.2026. Контекст не переносится между задачами, системная инструкция общая; эталоны в запросы не включаются. Точные форматы хранятся в тетрадях и журналах.

В банке 36 задач: A — 6 расчётных, B — 6 утверждений, C — 6 объяснений, D — 6 программ, E — 3 отдельных объекта, F — 9 ловушек. Темы: kNN, SVM, байесовские методы, деревья, ансамбли, PCA, кластеризация, регрессия и метрики. Подробное соответствие «тип × тема» находится в `data/questions.csv`. Для E дополнительно выделены 150 тестовых объектов breast cancer и непересекающиеся 20 обучающих примеров; 5-shot — подмножество 20-shot. Редкий класс в этом тесте — 0, в отличие от отдельной синтетической задачи D02, где редкий класс — 1.

Числа A сверяются с эталонами с относительным допуском 1%; B автоматически проверяется по метке, затем отдельно по рубрике 0–2. E проверяется по истинному классу. Программы D запускаются отдельными процессами без исправлений исходного ответа; проверяются завершение, вывод и методология. В данном протоколе выражение в конце файла без `print` не считается выполнением требования «выведите». Markdown-ограждения в ответе на инструкцию «только Python-код» не удаляются. Эталонные решения пересчитаны в том же окружении (`verify_solutions.py`).

Первый лист проверки B/C/D/F заполнен **ИИ**, а не независимым участником. Второй лист пуст. Поэтому каппа двух людей пока не определена; предварительные баллы не заменяют требование слепой человеческой проверки. Для F дополнительных задач применяется только эвристика, ожидающая содержательной проверки.

## 3. Результаты

### Основной банк: предварительная оценка

| Модель | Правильно / всего | Accuracy | 95% bootstrap CI | Средняя задержка | Среднее число токенов |
|---|---:|---:|---:|---:|---:|
| GigaChat | 29/36 | 80.6% | 66.7–91.7% | 2.08 с | 205.7 |
| GPT | 33/36 | 91.7% | 80.6–100% | 12.91 с | 277.6 |
| Qwen 4B | 18/36 | 50.0% | 33.3–66.7% | 7.04 с | 264.1 |

У каждой модели 21 из 36 оценок опирается на предварительную разметку ИИ. Всего 108 ответов; 45 имеют автоматическую оценку A/B/E, остальные 63 пока оценены ИИ. Метка B может быть верной при ошибочном обосновании: поэтому число ошибок по рубрике отличается от числа неверных итоговых ответов. Доля отказов: 5.6%, 5.6%, 8.3% соответственно. Корректное указание недостатка данных в F засчитывается как верное решение.

Точный парный Макнемар: GigaChat–GPT p=0.21875; GigaChat–Qwen p=0.00342; GPT–Qwen p=0.000061. Это разведочный анализ без поправки на несколько сравнений и с предварительными экспертными метками. Разницу GigaChat/GPT нельзя объявлять статистически доказанной. Значимость не устраняет смещение проверки ИИ и малого банка.

В D программы GigaChat и GPT выполнились и дали требуемый вывод в 6/6 случаях. Qwen: pass@1=2/6, полностью требуемый вывод — 0/6; четыре программы не выполнились, две выполнились без полного требуемого вывода. Предварительно методологических утечек по чек-листу не обнаружено; это не означает отсутствия технических ошибок. Пиковая память Qwen — 7.598 ГиБ, без учёта времени скачивания весов.

Для основного GPT-прогона справочная стоимость одного правильного ответа — 0.120–0.167 руб. Диапазон связан с отсутствием разбивки токенов в части старых записей; это расчёт по [справочному тарифу OpenAI](https://developers.openai.com/api/docs/models/gpt-6.1-sol), не выписка LLM Gate. Для GigaChat-3-Ultra платный тариф не опубликован: официально она доступна только во freemium. Поэтому денежный эквивалент N/A, а не цена другой модели ([Сбер](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra), проверено 29.10.2026). Бесплатный лимит не означает нулевую справочную стоимость.

### E: полный дополнительный прогон GPT

Получены все 450 ответов: 150 × 0/5/20-shot. Неверных форматов метки нет.

| Модель | Примеров | F1 класса 0 | 95% CI F1 | Balanced accuracy |
|---|---:|---:|---:|---:|

| GPT | 5 | 0.9369 | 0.8823–0.9800 | 0.9483 |

Accuracy константного предсказания — 62.67%. Основные показатели — F1 редкого класса и balanced accuracy. Все CI считаются по 1000 bootstrap-выборкам, seed=42. Для сравнения с LogReg используется один и тот же bootstrap объектов, чтобы сохранить парность.

H12 для GPT: при 5-shot ΔF1=+0.0914, 95% CI [0.0403; 0.1511]; при 20-shot ΔF1=−0.0029, CI [−0.0577; 0.0452]. Доказательств второй части гипотезы («при 20 хуже») недостаточно. Эквивалентность моделей из включения нуля в CI не следует. Для общего вывода по нескольким LLM ещё нужны их прогоны.

### Новые контрольные задачи

GPT дал правильные итоговые ответы на 6/6 HA и 6/6 HB. На 6/6 HF эвристика обнаружила указание недостатка данных. H3 для GPT предварительно не поддерживается; нужна человеческая проверка отсутствия выдуманных чисел. H5 пока проверить нельзя: отсутствуют дополнительные ответы GigaChat и Qwen. Не заменяем их пилотными задачами после фиксации протокола.

Обязательные графики и таблицы находятся в [HTML-отчёте](../results/report.html). `classification_coverage.csv` показывает полноту E, `hypothesis_H*.csv` — доступные проверки гипотез. Пустая таблица означает отсутствие необходимых данных.

## 4. Пять ошибок

1. **GigaChat, A04, BernoulliNB.** Цитата: «0.5625*0.4/(0.5625*0.4+1/18*0.6)=0.9». Формула и условные вероятности верны, но арифметика даёт 0.8709677. Ошибка находится после построения модели, на вычислительном шаге.
2. **Qwen, A02, Джини.** Цитата: «0.32 - [0.071 + 0.119] = … = 0.13». Здесь 13/50 × 0.472 ≈ 0.12272, а не 0.119; точный прирост 0.1212474. Преждевременное округление и неточные умножения выводят ответ за допуск 1%.
3. **Qwen, B01, SVM.** Метка «верно», затем: «Увеличение параметра C … уменьшает штраф». В целевой функции штраф умножается на C, поэтому увеличивается. Проверка только первой метки скрыла бы содержательную ошибку; рубрика — 1/2.
4. **Qwen, D02, программа.** Цитата: «pipeline = Pipeline([ … ])», но импорт `Pipeline` отсутствует. Неизменённая программа завершилась с `NameError`. Метрики F1/BA выбраны по смыслу правильно, однако pass@1=0. Исправлять импорт перед оценкой первой попытки нельзя.
5. **Qwen, F07, стоимость ошибок.** Цитата: «порог не определяется (данные недостаточны …)». При откалиброванных вероятностях выбираем положительный класс, если 10(1−p) ≤ 90p, то есть p ≥ 0.1. Нулевая цена правильных решений не отменяет стоимости ошибок. Здесь отказ ошибочен, хотя в других F-задачах отказ правилен.

Это наблюдаемые дефекты конкретных ответов; внутреннюю причину работы модели по ним установить нельзя. Исходные тексты сохранены в журналах и `all_answers.csv`, результаты исполнения — в `code_execution.jsonl`.

## 5. Ограничения

1. Нет двух независимых слепых человеческих проверок; ИИ мог систематически ошибиться при оценке других моделей. Каппа не вычислена.
2. Банк мал и не является случайной выборкой задач ML; CI описывают этот банк, не весь класс задач.
3. Гипотезы сформулированы после пилота; прогнозы предложены ассистентом, исходное требование студенческой регистрации до начала работы не выполнено задним числом.
4. Нет результатов четвёртой модели и полного дополнительного прогона всех моделей. В PDF требуется минимум четыре модели и две российские; замену Яндекса на T-lite нужно согласовать.
5. Авторство не менее половины задач студентами и ссылки на заимствованные источники требуют подтверждения. Сгенерированные ИИ задачи не считаются написанными студентом автоматически.
6. GPT доступен через посредника; серверная версия и фактическое списание проверяются только у провайдера. Часть исходного usage неполна. Параллельные дополнительные вызовы нельзя смешивать с последовательными измерениями задержки пилота.
7. Запуск D как файла строже интерактивной тетради: выражение в последней строке не печатает результат. Правило описано явно и применяется ко всем моделям.

## 6. Предварительные рекомендации для проверки авторами

| Тип задачи | Уровень доверия по этому пилоту | Что проверять |
|---|---|---|
| A, расчёты | Не доверять без вычислительной проверки | арифметику и допуск, даже при правильной формуле |
| B, утверждения | Проверять выборочно и обоснование | метка может противоречить тексту |
| C, объяснение | Проверять по рубрике | пропуски важных условий и утечки |
| D, код | Не доверять без запуска | импорты, формат, фактический вывод, train/test |
| E, классификация | Проверять на отдельном test | F1 редкого класса, BA и baseline |
| F, ловушки | Не доверять без разбора условий | различать обоснованный и ошибочный отказ |

Окончательный вывод по работе и рекомендации должны быть самостоятельно сформулированы авторами после завершения недостающих проверок.
